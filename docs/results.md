# Results: dedicated server

Generated by `scripts/report.py` from the JSON lines in `results/dedicated/`. Every number below comes from a script in `scripts/` and can be reproduced with it.

Primary results. An exclusive HPC node: fast, uncontended flushes (4 KiB overwrite+fdatasync p50 138 µs) but 2.2 GHz cores. At 1,024 requests in flight this CPU saturates in the gRPC request path: the non-replicated standalone control row shows the same tail as the 3-node cluster, and a separate diagnosis with fsync and snapshots disabled changed nothing, so the tail is not replication or the disk. At 32 clients the 3-node p99 is 6.8 ms. The same suite on a faster desktop CPU: [results-shared-box.md](results-shared-box.md).

- **cpu**: Intel(R) Xeon(R) Platinum 8276 CPU @ 2.20GHz

## Failure testing (`scripts/bench-chaos.sh`)

16 writers against a 3-node cluster; the leader is SIGKILLed every 3 s and restarted 1 s later (every 4th cycle SIGTERM instead, which hands leadership over first). Failover = kill to the first write acknowledged by another node. Lost = keys whose final value is below the last acknowledged write; stale = linearizable reads that returned a value older than an acknowledged write.
